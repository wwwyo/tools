# ケイリョウ（keiryo）

画像を検品して、軽くします。サイズ違いを一列に並べて選ぶだけのツール。

## 使い方

- 画像をドラッグ&ドロップ / クリックで選択 / Cmd+V で貼り付け、または「サンプル画像で試す」
- 読み込むと、サムネイルと検品テーブル（ファイル名・拡張子・実際の形式・MIME・容量・寸法・画素数・アスペクト比・最終更新・透過の有無・色深度・EXIF 向き）が出る。拡張子と実形式が食い違っていれば警告行が出る
- 出力形式（JPEG / WebP）と品質スライダーを1組だけ操作すると、長辺 原寸 / 2048 / 1600 / 1200 / 800px の梯子（ラダー）が全行その設定で再エンコードされる
- 先頭の「元ファイル」行だけは再エンコードせず、読み込んだバイト列そのものをダウンロードできる比較用の基準行
- 解析・変換はすべてページ内 Canvas で完結し、画像は外部に送信しない

## 設計と判断

### 品質つまみを1つにした理由

行ごとに「高画質 JPEG 0.9」「軽量 WebP 0.75」のようなプリセットにすることもできるが、この梯子で本当に見せたいのは「同じ画質設定のまま長辺だけ変えるとどう軽くなるか」という縮小の効きであって、行ごとに画質基準が違うと比較にならない。形式と品質を画面全体で1組にし、変わるのは長辺だけにした。

### PNG を出力形式に出さない理由

品質スライダーは非可逆圧縮のパラメータで、可逆圧縮の PNG には意味を持たない（`canvas.toBlob` は PNG に quality を渡しても無視する）。選べるのに効かないつまみを置くと「効いていないのでは」と疑わせるだけなので、最初から選択肢に出さない。

### 縮小ステップは常に原寸を残し、アップスケールする段は省く

梯子の目的は「小さくする」ことなので、画像の長辺より大きいステップを出してもアップスケールでボケるだけの行が増える。該当ステップは候補から外す一方、原寸（無変換ではなく同じ形式・品質での再エンコード）は基準として常に出す。

### 逐次エンコード（Promise.all にしない）

5行を並列で `canvas.toBlob` すると、大きな画像では同時に5枚分のフルサイズ canvas を確保することになりメモリを食う。1行ずつ await して順番に確定させ、品質・形式変更のデバウンス中に前回の実行が終わっていない場合は shirobikari と同じ「実行中なら直後にもう一度だけやり直す」直列化で対応する。

### ヘッダー読み取りは 64 KiB

フォーマット判定と PNG IHDR は先頭 32 byte で足りるが、JPEG の Exif（APP1）セグメントは 16bit 長で最大 64 KiB になりうる。Orientation タグまで届かせるため、ヘッダーはまとめて 64 KiB 読む。画像全体を ArrayBuffer に載せないのは、巨大ファイルでメモリを二重に持たないため。

## ファイル構成

```
keiryo/
├── index.html    エントリ（title / description は一覧・OGP 自動生成に使われる）
├── main.ts       UI・状態管理・逐次エンコードの直列化
├── imageMeta.ts  マジックナンバー判定・PNG IHDR・JPEG Exif Orientation・透過検知・検品メタデータ組み立て
├── encode.ts     長辺キャップ付きリサイズ・canvas 再エンコード・サンプル画像生成
├── styles.css    :root テーマ上書き・行の入場アニメーション・比率バーの transition
└── og.tsx        OGP カード用の画面ミニチュア
```
