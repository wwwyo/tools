# 成果物が正しいことと、配信先がそれを保持することは別問題

- Status: Accepted
- Date: 2026-07-22

生成した UltraHDR JPEG は macOS ImageIO が `isoGainMap=true` と認識するところまで確認済み、つまり**ファイルは正しい**。それでも X に投稿すると HDR にならない。ファイル不良を疑ってサイズ・長辺・ICC 型（LUT 型 → `matrix/TRC` 型 P3 PQ）と条件を変えて追試したが通らず、最終的に **X 側の再エンコードで gain map / ICC が落ちている**という切り分けに至った。これは 07-19 の Cloudflare Bot Fight（deploy は成功しているのに OGP クローラが弾かれる）と**同じ型**で、いずれも「自分の環境で正しい」と「外部から観測される」の間に一段ある。一般化して [/tech/artifact-vs-delivery-fidelity.md](https://github.com/wwwyo/me/blob/main/wiki/tech/artifact-vs-delivery-fidelity.md) に切り出した。実務上の帰結として、**X 向けの特殊最適化は打ち切り**、一般的な HDR 変換ツールとしての価値を優先する方へ戻した（相手の再エンコード仕様は観測できず、追試のコストが青天井になるため）
