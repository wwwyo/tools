# バイナリを手組みするなら、生成物を独立にパースし直すテストを書く

- Status: Accepted
- Date: 2026-07-22

UltraHDR JPEG は base JPEG + gain map + XMP(APP1) + MPF(APP2) を `Uint8Array` で連結して作るが、**XMP の `Item:Length` と MPF のオフセットは最終的な連結バイト列の位置に厳密一致していないと gain map が黙って無視される**（エラーにならず「ただの JPEG」として表示されるので、目視では気づけない）。実際に MPF のオフセット計算にバグがあり、**生成バイト列を独立にパースし直す単体テスト**が検出した。実装と同じ計算式で検算すると同じ間違いをするので、検証側は別経路で書く。ホットパスの `sRGB → linear` は入力が 8bit＝256通りしかないので **LUT 化**し、base JPEG と輝度マップは画像ロード時に1回だけ計算してキャッシュ（スライダー操作のたびの全再計算をやめた）。連打対策は debounce でなく**変換の直列化 + 走行中は「次回1回だけ再実行」**に倒した
